# Development E2E Production-Readiness Defect Ledger

Environment: development (`localhost:3001`) only. External customer communication, Zoho production mutation, label purchase, and payment remain blocked until their explicit safe test stage.

| ID | Severity | Module | Defect | Status |
|---|---|---|---|---|
| E2E-001 | P1 | Lead conversion | Replaying conversion for an already-converted lead could create another Account because the route did not return the existing conversion and local account external IDs used the current timestamp. | Fixed and regression-tested; replay returns the linked Account with `alreadyConverted` and never starts another conversion transaction |
| E2E-002 | P2 | Lead intake | The employee Sales UI exposed CRM lead sync and Account creation but no complete manual Lead creation workflow, despite the Lead API supporting creation. This prevented the requested first-touch lifecycle from being performed entirely through the UI. | Fixed; browser creation journey passed |
| E2E-003 | P1 | Lead intake API | Manual lead creation accepted an empty company, malformed email/phone, and did not perform duplicate detection before persistence. | Fixed; focused tests pass |
| E2E-004 | P2 | Development queue | The Next Best Action screen initially showed an empty queue while the CRM Leads list contained 200 records; intended eligibility/ranking behavior requires reconciliation. | Closed; live retest shows 100 callable accounts and 41 urgent accounts, with the prioritized queue rendered and selectable |
| E2E-005 | P2 | Manual lead intake | A newly entered rep-owned lead was not reserved into that rep's calling workstation, so the rep could create it successfully and then lose it among the unclaimed pool. | Fixed; browser queue journey passed |
| E2E-006 | P1 | Lead callback | The UI reported a scheduled callback as saved, but no Task was persisted. Callback dates were not server-required, tasks used non-idempotent timestamp keys, and Task had no Lead relationship. | Fixed; migration applied in dev, browser save/replay/cancellation passed with exactly one Task |
| E2E-007 | P1 | Lead callback UI | The datetime-local field visibly accepted an automated/user-style entry but its controlled React state remained empty, causing a correct API validation error on save. | Fixed; switched to input-event binding and browser save passed |
| E2E-008 | P3 | Account workspace | Desktop repeated Call, SMS, and Quick Sale actions in both the header/tab bar and account rail, spending space without adding capability. | Fixed; desktop uses the contextual rail and canonical tab, while compact layouts retain header actions |
| E2E-009 | P2 | Order builder | “Popular Gifts” rendered the entire gift catalog as a quick-add rail, overwhelming the primary product-selection task. | Fixed; quick suggestions capped at 10 while full catalog search remains available |
| E2E-010 | P1 | Transaction integration | Development could not exercise the document lifecycle because every confirmation required live Zoho OAuth, despite providers being intentionally disabled. | Fixed; explicit non-production-only local transaction simulation persisted a $249.99 Sales Order and line item without contacting Zoho |
| E2E-011 | P2 | Order builder | A successfully created order stayed in the cart when the builder received an initial external line array without an external setter. | Fixed and regression-tested; a successful local transaction clears the uncontrolled cart and preserves the success callback |
| E2E-012 | P3 | Order builder | “Confirm & Push” implied a guaranteed external action even when the environment may create locally or return an integration error. | Fixed; action now says “Confirm & Create,” with the resulting toast naming local development or Zoho explicitly |
| E2E-013 | P1 | Order processing | The order reached Processing with its line item and account name, but the Customer & Delivery panel said email, phone, billing, and shipping were missing because it read only the document JSON and ignored the linked Account. | Fixed and live-data verified; the existing simulated order resolves its linked account, primary contact, email, phone, shipping address, and billing address through the lifecycle fallback |
| E2E-014 | P2 | Order builder | A legacy free-customer-gift purchase without a current catalog gift flag appeared in the ordinary Previous Purchases rail, bypassing the collapsed profit-qualified promotion workflow. | Fixed and browser-verified; Previous Purchases dropped from 33 to 32, the TV gift disappeared, specialty blades remained first, and the collapsed qualifying-promotion surface remained available |

Evidence and retest results will be added as the two customer journeys proceed.
